# A股选股系统

## 执行选股

1. 运行第一池评分：`cd ~/Pictures/选股 && python3 stock_screener.py`
2. 运行第二池评分：`cd ~/Pictures/选股 && python3 pool2_screener.py`
3. 读取 `results/weekly_*.csv` 和 `results/risk_*.json`
4. 从新浪API获取每只股票**本周5天收盘价**（周一到周五），不是只取周五一天
5. 更新飞书表格（执行 `python3 ~/Pictures/选股/update_feishu_sheet.py`）

## 系统架构（V3 - 评分与风险完全分离）

```
选股系统 → 输出Top20（纯评分，不跑风险评估）
    ↓
对比最早历史记录 → 找出评分/股价大变的股票
    ↓
风险诊断 → 按指标体系文档检查8类指标 → 判断是好/坏/没关系
    ↓
飞书表格 → K-M列显示诊断结果（只有触发诊断的股票才有内容）
```

### 核心原则

1. **评分系统**：反映股票综合质量，权重：资金35% + 趋势25% + 成长20% + 估值15%
2. **风险系统**：是**诊断工具**，不是门卫。只在对比上周时触发，告诉你"为什么变差了"
3. **触发条件**：评分掉≥5分 或 股价跌≥10%
4. **判断逻辑**：看具体是哪个指标导致的，那个指标本身是好是坏（不是"评分跌了=变坏"）

用户原话："评分上升下跌和股价涨跌只是触发他判断的条件，不是说上升就是变好"

### 风险等级与操作建议

| 等级 | 信号含义 | 操作建议 |
|------|----------|----------|
| 🟢 normal | 短期波动，可以继续买 | 正常交易 |
| 🟡 watch | 逻辑开始变弱 | 暂停新建仓，已有仓位继续观察 |
| 🔴 risk | 核心逻辑被破坏 | 暂停新建仓，已有仓位考虑减仓 |
| 🚨 sell | 必须离场 | 建议卖出，核心逻辑已破坏 |

### 风险触发机制（按指标体系文档）

| 指标 | 🟢 正常 | 🟡 观察 | 🔴 卖出 |
|------|---------|---------|---------|
| 均线趋势 | 在60日/120日线上 | 跌破20日线 | 跌破60日/120日线 |
| 成交量 | 缩量整理 | 连续缩量 | 放量下跌 |
| 高位回调 | 正常波动 | 回调20-30% | 回调>30% |
| 利润增长率 | 正常波动 | 增速放缓(<10%) | 转负增长(<0%) |
| 资产负债率 | 小幅变化 | 略升(>65%) | 明显恶化(>80%) |
| 股东人数 | 持平 | 小幅增加(>3%) | 连续明显增加(>10%) |
| 北向资金 | 正常 | 连续流出 | 持续大幅流出(>1亿) |
| 重大公告 | 一般公告 | 一般风险提示 | 立案调查/造假/暴雷 |

## 新浪API获取周股价

```python
# 代码→市场前缀：6开头=sh，其他=sz
symbol = f'sh{code}' if code.startswith('6') else f'sz{code}'
url = f'https://money.finance.sina.com.cn/quotes_service/api/json_v2.php/CN_MarketData.getKLineData?symbol={symbol}&scale=240&ma=no&datalen=5'
# 返回最近5个交易日的{day, open, high, low, close, volume}
# 取每条的close，按日期排序后对应F(周一)~J(周五)
```

**日期映射**：API返回最近5个交易日，按日期排序后：
- 第1天 → F列（周一）
- 第2天 → G列（周二）
- ...
- 第5天 → J列（周五）

## Pitfalls

1. **不要双重扣分**：风险评估不参与评分，只给操作建议。评分系统已经因为均线跌破等因素扣分了，风险系统不能再扣
2. **F-J列是整周股价**：周五选股时从新浪API获取本周5天收盘价（周一到周五），不是只取周五一天
3. **飞书写入权限**：tenant_token只能读，写入必须用user_access_token
4. **飞书批量写入**：批量写入可能400错误，建议逐行写入
5. **飞书Token过期处理**：user_access_token过期→先试refresh_token→如果也过期（30天/一次性）→走OAuth重新授权。OAuth流程见 `feishu-integration` skill。macOS上用AppleScript控制Chrome自动点授权按钮，不要用browser_navigate（headless Chrome访问不了localhost回调）
6. **OAuth一次搞定**：授权失败不要反复重试，检查服务器是否启动、Chrome是否打开正确页面、按钮是否点到。一次成功就继续干活，不要来回折腾
7. **突破位计算**：用60日高点，不是120日绝对高点
8. **大幅回调**：从高点回调>20%时突破位判断不适用
9. **K线列名兼容**：支持中英文（c/close, v/volume）
10. **B规则卖出**：必须连续2周跌出Top20，累计跌不触发
11. **datetime比较必须用.date()**：`day_date >= monday` 会因为时间组件导致比较失败（如 2026-06-22 00:00:00 < 2026-06-22 15:53:40），必须用 `day_date.date() >= monday.date()`
12. **历史对比用最早记录**：不要用 `recent[-2]`（上一次运行），要用 `recent[0]`（最早记录）才能捕获跨周的评分变化
13. **风险诊断不是门卫**：风险系统是诊断工具，只在对比上周时触发，不是对所有股票都跑一遍
14. **飞书写入范围动态计算**：`write_row` 的列范围必须用 `chr(64 + len(data))` 动态计算，不能硬编码 `M`。第一池和第二池表头统一为A-Q（代码/名称/综合评分/风险等级/风险建议/周一~周五/风险事件1-3/建议/开盘价/当前价/滑点）
15. **第二池飞书表格不要重写**：第二池有手动维护的N-T列数据（建议、开盘价、当前价、滑点），update_feishu_sheet.py只更新第一池，跳过第二池。⚠️ 但如果第二池F-J列被更新了，O/P/Q列会跟F-J完全对不上（视觉上数据错位），这是已知问题，需要修脚本
16. **历史记录要存top20**：history.json的recent数组里除了top5还要存top20和top20_scores，方便后续对比更多重叠股票
17. **update_feishu_sheet.py O/P列数据源错误**：脚本把周一收盘价写入O列(开盘价)、周五收盘价写入P列(当前价)，这不是真实的开盘价/当前价。真实开盘价应该是信号日次日的开盘价（从新浪API的open字段获取），真实当前价应该从实时行情获取。Q列(滑点)从未计算，一直为空。修复前先确认用户期望的数据来源
18. **飞书refresh_token一次性消耗**：refresh_token只能用一次，用完立即失效。如果token刷新后没有及时保存新token，或者session间隔过长导致新token也过期，就需要完整走OAuth重新授权流程。每次OAuth成功后必须立刻把新token写入feishu_user_token.json
19. **CSV文件有BOM**：选股系统输出的CSV文件开头有UTF-8 BOM（`\ufeff`），读取时必须用 `encoding='utf-8-sig'`，否则第一列的列名会变成 `\ufeff代码` 而不是 `代码`，导致 `row.get("代码")` 返回 None
20. **OAuth授权按钮可以用browser_navigate点击**：不需要用AppleScript。先启动OAuth服务器（background），然后用 `browser_navigate` 打开授权URL，页面会显示授权按钮（ref如 `@e3`），用 `browser_click` 点击即可。如果页面跳转到登录页，说明Chrome的飞书登录态过期，需要用户扫码登录后重试
21. **选股表格在用户个人云盘**：表格 `APv3sZM02h4DQrt8Bcrclin4nfW` 在用户个人飞书云盘「三板斧」文件夹，不是应用云盘。应用的tenant_token只能读不能写，必须用user_access_token写入
22. **KLM列必须写风险诊断结果**：K(风险事件1)、L(风险事件2)、M(风险事件3) 列的内容必须来自风险系统的实际诊断（risk_monitor.py 或历史对比结果），不能自己编造原因。用户原话："风险事件是说他的评分因为什么原因降低的，不是你这样写的"。如果风险系统没有覆盖到（如掉出去的股票），要先跑诊断再写，不能空着也不能瞎写
23. **掉出去的股票要标红+加在末尾**：Top20变动时，掉出去的股票要加在第21行（或末尾），字体标红（`fontColor: #FF0000`），KLM写清楚掉出原因。20只变1只很难发现，必须显眼提示
24. **风险监控脚本现在会扫掉出去的股票**：`risk_monitor.py` 的 `load_current_portfolio()` 会对比本周和上周的Top20（第一池weekly_ + 第二池pool2_），自动检测跌出的股票并一起扫描。输出中会打印 `⚠️ 发现跌出: XXX`。但仍需确保 `results/` 目录下有上周的CSV文件，否则无法对比
26. **更新飞书表格后必须跑风险监控**：更新完表格后，跑 `cd ~/Pictures/选股 && python3 risk_monitor.py` 获取掉出股票的风险诊断，然后把诊断结果写入KLM列。不能跳过这步直接编原因
25. **飞书表格标红API格式**：设置字体颜色用 `styles_batch_update`，body格式：`{"data": [{"ranges": "sheet_id!A21:Q21", "style": {"fontColor": "#FF0000"}}]}`。注意是 `fontColor` 不是 `foreColor`，外层是 `data` 数组不是 `appendStyle`
