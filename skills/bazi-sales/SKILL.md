# 🚀 快速开始（多Agent版本）

## 一句话说流程

输入客户年月日时 → 协调器自动调用6个Agent → 输出完整销售方案

## 核心流程

### ⚠️ 直断过三关（快速验证阶段）

**当客户刚报出八字，需要先"过三关"验证时，加载 `bazi-zhiduan` skill。**

过三关流程：
1. 客户报出八字
2. 快速扫描直断速查表
3. 命中2-3条直接下结论
4. 客户确认"对"→ 建立信任 → 进入正式分析

**触发条件：**
- 客户刚报八字，还没开始详细分析
- 客户说"你先看看准不准"
- 需要快速验证建立信任
- 客户问具体问题（如"我婚姻怎么样"）→ 直接用对应速查表答

**可用速查表：**
- 28秘诀（父母/配偶/子女/兄弟/婚姻/健康）
- 十天干性格
- 痣位置
- 身材体型
- 面相特征
- 性冷淡/性敏感
- 卧室物品
- 婚姻断语
- 健康断语

### ⚠️ 排盘数据源要求（必须遵守！）
1. **第一步必须运行JS排盘脚本**：`node scripts/generate_bazi_analysis.js <年> <月> <日> <时> <性别>`
   - 输出到 `references/<年月日时性别>.md`
   - 此MD文件是后续所有Agent的唯一数据源
2. **绝对禁止**：用Python手算排盘、用AI直接推算天干地支
3. cnlunar仅作备用验证，不作为主排盘工具
4. 四柱确认后才能进入话术生成

### ⚠️ 知识库引用规则
- **references/目录中，.md文件是原始知识库（理华千山派28式等）**
- **.json文件是AI根据md生成的，可能有错误**
- **当json和md有冲突时，以md为准**
- 引用断语时优先读MD原文，JSON只做辅助参考
- **十神组合判定框架.md** — 十神特殊组合的判定方法：先定格局再看组合是否攻击格局核心。含6个格局的成立/不成立矩阵、替代分析方法、核心断语。**分析八字组合时必查。**
- **五行归类速查.md** — 常见事物的五行归类（股票/金融属金、房地产属土等）+ 常见误区。**分析五行生克时必查，不要凭直觉归类。**
- **13_补充知识库.md** — 补充了墓库、空亡、十神组合、大运流年、五行、格局等skill原12个文档缺少的内容。当需要查找这些专题的断语时，先查此文件，再查原12个文档。
- 14_寿命七步法.md — 八字寿命判断完整流程（七步法+断语+调理方法）。当客户询问寿命、健康、寿元相关问题时，必须使用此文档的七步法进行判断。
- bazi-zhiduan — 直断速查手册（28秘诀/十天干性格/痣位置/身材体型/面相/性相关/卧室物品/婚姻/健康断语）。**过三关阶段必须使用。**
- **15_六亲递推速查.md** — 十天干六亲递推速查表。核心规则：每一代偏财=父亲、正印=母亲，逐层递推。含十天干完整六亲对照表。**分析六亲（父母/祖辈/配偶/子女）时必查。**
- **易学五行分类注意：** 易学本体属水（玄学/预测/隐学），传播属火（文化/教学/自媒体）。不要把所有"文化"都归为火。推荐行业时，做预测咨询=水（用神方向），做讲师做IP=火（忌神方向），需分开看。
- **D:\\hermes-agent\\bazi-vault-v3\\** — 从44篇课程笔记中提取的完整知识库（约850+条断语），包含：
  - `标签索引/` — 按主题分类的断语（事业、婚姻、财运、健康、子女、五行、十神组合、墓库、空亡、格局、贵格、神煞、风水、物品取象等20个文件）
  - `extracted/` — 原始提取的知识点文件
  - 查询时优先使用标签索引中的分类文件

### ⚠️ 寿命判断Agent
当客户询问寿命、健康、寿元相关问题时，协调器应调用 Agent6-寿命判断专家（`bazi-sales-agent6-lifespan`），执行七步法判断流程。
  - 第13课_婚姻.md → 婚姻次数判断步骤
  - 第7课_格局.md → 甲木贵格判断黄金法则5步

### ⚠️ 断语引用注意事项
1. **断语必须完整**：每条断语需要包含前置条件+结论，不能只引用结论部分
   - ❌ 错误：适合从事管理、谈判专家（缺少条件）
   - ✅ 正确：【七杀有制化为权】适合从事管理、谈判专家
2. **使用标准术语**：八字格局命名要规范
   - 伤官格（不是"伤官见官"，因为包含伤官配印、金水伤官等多种类型）
   - 官杀格（不是"官印格"，因为包含正官、七杀的各种组合）
   - 食神格（包含食神制杀、食神生财等）
3. **贵格查询**：十天干贵格详见 `references/13_补充知识库.md` 中的"贵格"章节

### ⚠️ 知识库组织方法（四Agent协作）
当需要从课程笔记中提取和分类断语时，使用四Agent协作：
1. **Agent2（搬运工）**：逐条提取断语，标注来源和关键词，输出到 all_assertions.txt
2. **Agent1（标题审核）**：只看标题关键词，判断断语是否匹配该主题，输出到 review_results.txt
3. **Agent4（条件检查）**：检查每条断语是否有完整的前置条件+结论，标记缺少条件的断语
4. **Agent3（监控）**：检查遗漏，确保完整性，输出质检报告

分类规则：
- 按断语**内容**分类，不是按来源文档名分类
- 一条断语可出现在多个标签文件中（如同时涉及婚姻和事业）
- 每个标签文件只放该主题相关的断语，不混入其他内容
- 断语必须有完整条件，不能只有结论（如"适合从事管理"缺少"七杀有制化为权"的条件）

### 流程说明
```
你: 1987年9月12日6时男命
    ↓
协调器第一步：运行JS脚本排盘 → 生成 references/19870912男命.md
    ↓
协调器自动调用（内部静默，不输出中间结果）：
  Agent1-解析 → 特征卡（基于MD文件数据）
  Agent6-寿命判断 → 寿元分析（客户问健康/寿命时触发）
  Agent2-话术生成 → 话术集（根据诊断+寿元分析）
  Agent4-质检 → 验证准确性（对照MD文件）
    ↓
质检通过 → 输出最终合并方案（诊断+话术）
    ↓
你: 客户说：是的，我就是这样
    ↓
协调器调用 Agent3-成交专家
    ↓
输出: 下一步话术指导
```

### 三步完成销售

**第1步** - 提供客户信息（只需一句话）：
```
你好，我要分析 1987年9月12日6时 男命
```

**第2步** - 获得完整的销售方案（系统自动生成）：
```
系统输出：
  ✅ 诊断报告
  ✅ 开场话术
  ✅ 校准话术（2-3段）
  ✅ 深入话术
  ✅ 成交话术
```

**第3步** - 模拟对话，实时调整：
```
你: 客户说"对，我就是这样"
系统: 分析信任度 → 生成下一句话术
```

## 使用方式

### 直接对话（推荐）
```
/bazi-sales
然后直接输入：1987年9月12日6时 男命
```

### 单独调用某个Agent
```
/bazi-sales-orchestrator  ← 完整流程
/bazi-sales-agent1-parsing  ← 只做解析
/bazi-sales-agent2-librarian  ← 只做知识库查询
/bazi-sales-agent5-speechgeneration  ← 只做话术生成
/bazi-sales-agent3-closing  ← 只做成交指导
/bazi-sales-validator  ← 只做质检
```
