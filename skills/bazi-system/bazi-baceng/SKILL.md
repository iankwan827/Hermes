# 八字断事八层体系

## 核心定位

八字命理推算的完整分析框架。**画像先行，后续层基于画像做场景推演。**

> 讲师原话：「有些拍了八字就断什么时候离婚，太容易太浅薄了。你连一个人都给他刻画不出来，他是一个什么货色，靠断什么时候离婚有什么用？」

---

## 分析流程总览

```
第一二层：基础（排盘+格局）→ 地基
    ↓
画像层：人物画像 → 这个人是谁
    ↓
第三-八层：专项分析 → 这种人面对XX会怎样（基于画像推演）
```

**核心原则：同一命理特征，不同性格的人会做出不同选择。画像决定了面对命理特征时的行为方式。**

---

## 第一二层：基础层（必做）

### 第一层：基础排盘层

1. **四柱八字排盘**：根据出生年月日时转化为天干地支
   - 年柱主祖上根基/少年运
   - 月柱主父母家庭/青年运
   - 日柱主命主自身/中年运
   - 时柱主子女后辈/晚年运
2. **五行分布与旺衰统计**：统计金木水火土的力量占比
3. **日主强弱判断**：以月令为核心标尺
4. **十神系统全面排布**
5. **地支藏干解析**
6. **纳音五行参考**

### 第二层：格局核心层

- **正格**（八类）：正官格、七杀格、正印格、偏印格、正财格、偏财格、食神格、伤官格
- **变格**：从财格、从杀格、从儿格、专旺格、化气格等
- **调候用神**：根据出生季节的寒暖燥湿选取调整五行
- **干支作用关系**：天干生克制化、五合；地支六冲六合三合、三会、相刑相害相破
- **神煞系统**：天乙贵人、文昌、桃花、驿马、羊刃等

### 第一二层输出

```json
{
  "layer": 1,
  "name": "基础排盘层",
  "bazi": { "年柱": "...", "月柱": "...", "日柱": "...", "时柱": "..." },
  "shishen": { "年干": "...", "月干": "...", "日干": "...", "时干": "..." },
  "shenruo": "身强/身弱",
  "yongji": { "用神": "...", "忌神": "..." }
}
```

```json
{
  "layer": 2,
  "name": "格局核心层",
  "geju": "...",
  "features": ["偏印重重", "正财过旺", ...]
}
```

## 画像层：人物画像（排盘+格局之后必做）

**⚠️ 画像层不是可选的，是第一二层之后的必做步骤。**

### 为什么画像要在前面

- 画像回答"这个人是谁"，后面的层回答"这个人会怎样"
- 没有画像，后面的分析就是通用断语，缺乏针对性
- 画像决定了面对同一个命理特征时，这个人会做出什么选择

### 画像生成

加载 `bazi-portrait` skill，读取第一二层的JSON，执行：

1. 性格5维度分析（日元天干、日坐十神、两头挂、四柱心性、相处方式）
2. 十神深度补充（根据命局突出十神加载对应skill）
3. Writing框架串联 → 输出完整人物画像

### 画像输出

```json
{
  "layer": "portrait",
  "name": "人物画像",
  "core_personality": "庚金日主，刀剑之金，刚毅有原则但过刚则折",
  "temperament": "日坐正官，守规矩但闷雷型爆发",
  "four_layers": {
    "public": "...（公众人设）",
    "social": "...（社交性格）",
    "self": "...（真实本我）",
    "hidden": "...（深层隐秘）"
  },
  "key_combinations": ["官印相生：...", "财多身弱：..."],
  "core_contradiction": "表面服从内心不服，体制内是牢笼不是归宿",
  "advice": "..."
}
```

### ⚠️ 画像与后续层的关系

**画像不是结论，是推演基础。** 但不同领域与画像的关联度不同：

| 后续层 | 与画像关系 | 说明 |
|--------|-----------|------|
| 第三层（六亲） | **弱关联** | 父母/配偶/子女有自己的命理特征，画像只影响最后的相处模式 |
| 第四层（事业财运） | **强关联** | 这种性格的人面对工作/金钱会怎么选 |
| 第五层（运势） | **强关联** | 这种性格的人遇到好/坏运会怎样反应 |
| 第七层（调理） | **强关联** | 这种性格的人适合什么样的调理方式 |

## 第三层：六亲关系层

### 必须加载skill

`bazi-liuqin`（六亲分析方法）+ `bazi-sizhu`（宫位映射）+ `bazi-shishen`（十神基础）

### 分析内容

- **父母缘与家庭根基**：父强做事难，父弱多他相
- **兄弟姐妹**：以比肩劫财为基础分析
- **配偶与婚姻**：男命以财星为妻，女命以官星为夫，结合日支夫妻宫
- **子女与后代**：男命以官杀为子女，女命以食伤为子女，结合时柱子女宫

### 断事流程（宫位为主，星神为辅）

```
Step 1: 确定要断什么（六亲/事件）
Step 2: 找到对应的宫位（年祖/月父/日配/时子）
Step 3: 看宫位本身的旺衰、冲克、空亡
Step 4: 看宫位上的十神 → 用这个十神判断该六亲/事件的处境
Step 5: 找该六亲的星在哪 → 辅助验证
Step 6: 综合判断
```

### ⚠️ 六亲是独立分析，不依赖画像

六亲分析的是**父母/配偶/子女自己的命理特征**——他们的性格、处境、缘分。跟命主的画像没有直接关系。

**唯一关联：相处模式。** 六亲分析完成后，最后加一句命主与该六亲的相处方式：

> "月柱有七杀，父母给他压力——但他这种偏印性格，不会正面冲突，偏印的人'吵架不行，在意别人感受'，结果就是心里不爽但嘴上不说。"

这是画像的唯一用处，不是用来推演六亲本身的。

## 第四层：专项运势层（基于画像推演）

### 分析内容

- **学业**：结合印星、官杀、文昌星
- **事业**：结合大运，分析事业平台、是否适合创业
- **财运**：结合正财偏财、财库
- **健康**：以五行对应五脏，结合干支刑冲克害
- **人际贵人**
- **出行变动**

### ⚠️ 必须引用画像

不是输出"正财为忌，财运不佳"，而是：
> "他这种人——偏印底色、财多身弱——对钱的态度是'想要但扛不住'。正财为忌意味着稳定收入反而成负担，他不适合死工资，靠偏门技术赚钱更合适。"

---

## 第五层：运势推演层（基于画像推演）

### 分析内容

- **大运排布**
- **流年吉凶**
- **关键节点**
- **命局层次定级**

### ⚠️ 必须引用画像

不是输出"2026年丙午年，官杀旺，压力大"，而是：
> "他这种'表面服从内心不服'的性格，遇到官杀旺的流年，不会硬刚但会记仇。2026年丙午年叠加原局正官压力，加上偏印'不喜欢被管'的底色，今年很可能做出离开的决定——不是被开除，是主动走的。"

## 第七层：调理建议层（基于画像推演）

### 分析内容

- **五行补泄方案**：颜色、数字、方位、饮食、饰品、行业
- **行事策略**：运势导向给出不同阶段的行事原则
- **重大事项择时**：结婚、开业、搬家、投资等
- **风水环境调整**

### ⚠️ 必须引用画像

不是输出"补火，穿红色"，而是：
> "他这种偏印性格，需要的不是'补火'这种泛泛的建议。偏印为用，适合从事需要洞察力和独特视角的工作——研究、技术、玄学。行业选择比颜色重要得多。"

---

## 根据问题类型选择分析深度

| 用户问题 | 分析到哪层 | 说明 |
|---------|-----------|------|
| 过三关/快速验证 | 第一二层 | 基础验证 |
| 看性格/什么人 | 第一二层 + 画像 | 基础 + 人物画像 |
| 看六亲/婚姻/配偶 | 第一二层 + 第三层 | 基础 + 六亲（画像仅用于相处模式） |
| 看事业/财运 | 第一二层 + 画像 + 第四层 | 基础 + 画像 + 专项 |
| 看今年运势 | 第一二层 + 画像 + 第五层 | 基础 + 画像 + 运势 |
| 全面分析 | 全部层 | 完整分析 |

## Pitfalls

- **画像不是结论，是推演基础**：画像回答"这个人是谁"，专项分析回答"这个人会怎样"
- **六亲不依赖画像**：父母/配偶/子女有自己的命理特征，画像只影响相处模式
- **六亲宫位要拆分**：父亲=月干，母亲=月令，不能把月柱当一个整体
- **画像必须用skill断语**：不能凭印象写，每个断语必须来自对应的skill yulu.md
- **不要前言不对后语**：画像说偏印为用，后续分析就不能说他适合体制内
- **排盘数据是基础**，没有bazi.json不要开始分析
- **丁火不能当丙火用**：丁火是炉灶之火/蜡烛之火，贴身作用

---

## 架构原则

- **分析侧**：协调器按流程执行，结果存JSON
- **画像层**：排盘+格局之后必做，输出portrait.json
- **后续层**：读取portrait.json，用画像做上下文进行场景推演
- **输出侧（Responder）**：不关心skill加载步骤，只读JSON，用命理师视角输出
