# 八字软件架构模式：Skill → JS模块

## 核心原则

把bazi-system的多Agent skill体系翻译成JS模块化应用，**不建规则引擎**。
每个skill对应一个JS类，整个分析流程就是函数调用链。

## 应用结构（三个标签）

```
标签一：八字命盘    → 命盘展示（四柱/神煞/纳音/空亡/大运/地支关系）
标签二：身强喜用    → 身强身弱对比+喜用神详解
标签三：分析结果    → JS模块化分析输出
```

## 分析器模式

每个分析器遵循相同模式：
1. isObvious() — 判断这个十神/条件是否明显
2. analyze() — 执行分析，返回结构化JSON
3. 匹配templates/中的断语模板
4. 检查关联组合（如食伤生财、枭神夺食）

## 身强身弱：两种三得法对比（标签二核心功能）

### 传统三得法

| 维度 | 判定标准 |
|------|---------|
| 得令 | 月支本气是否与日主同党（同/被生） |
| 得地 | 地支藏干是否帮身 |
| 得生 | 印星是否生身 |
| **判定** | **三得二以上为身强** |

### 现代四得法

| 维度 | 判定标准 |
|------|---------|
| 得令 | 同上 |
| 得地 | 同上 |
| 得生 | 同上 |
| 得助 | 比劫是否帮身（新增） |
| **判定** | **四得三以上为身强** |

### JS脚本的权重评分制

`calculateBodyStrength()` 使用权重评分：
- 月支：45分（得令核心）
- 日支：20分
- 时支：15分
- 年支：10分
- 天干：10分
- 处理：合化、空亡减70%、冲库、贴身生助加成

## AI增强层（可选）

JS模块先输出结构化JSON → AI读取JSON生成流畅文本。
AI是"翻译"JS结果，不是替代JS分析。

```
JS JSON → prompt-builder.js → api-client.js → 流畅文本
                                      ↓ (失败时)
                              回退JS模板输出
```

## 断语模板库

从skill语录提取核心断语，存为JSON。每个十神有normal/many/asYong/asJi四种变体+组合断语。

## 跨平台技术选型

推荐 Capacitor + Vue（Web技术栈）：
- 排盘JS脚本直接用，零移植成本
- 分析模块也是JS，一套代码跑三个平台
- 打包后是原生应用，不是网页

```
bazi-app/
├── src/views/
│   ├── Login.vue       # 输入页
│   ├── Chart.vue       # 标签一：命盘
│   ├── Strength.vue    # 标签二：身强喜用
│   └── Analysis.vue    # 标签三：分析结果
├── public/scripts/     # 排盘JS脚本
├── src/core/analyzers/ # 分析模块
├── src/core/templates/ # 断语模板
├── src/core/           # 协调器
└── capacitor.config.ts
```

## 关键教训

1. **不要建规则引擎**：直接用JS类+函数调用，和现有paipan_node_core.js风格一致
2. **skill → JS模块是一一映射**：每个skill的分析逻辑翻译成一个JS类
3. **templates/是JSON不是JS**：断语文案存JSON，方便非程序员编辑
4. **AI是可选叠加层**：基础版纯JS跑，AI增强版在JS输出之上叠加
5. **降级策略**：AI失败→回退JS模板输出，保证离线可用
6. **身强身弱用三种方法对比**：传统三得法+现代四得法+JS权重评分，综合判定
7. **JS脚本的calculateBodyStrength()不要屏蔽**：它处理了合化、空亡、冲库等复杂情况，作为参考值保留，skill逻辑做最终裁决
8. **用户明确要求JS架构**：不要用传统规则引擎，用JS模块+函数调用链
