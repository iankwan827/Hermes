# 八字多Agent协调器

## 架构

```
用户输入 → bazi-master(协调器)
              ↓
    ┌─────────────────────┐
    │ Agent1: 排盘Agent    │ → 输出 bazi.json
    │ Agent1.5: 定位Agent  │ → 输出分析方向
    │ Agent2: 分析Agent    │ → 分层输出分析文本
    │ Agent3: 审核Agent    │ → 校验
    │ Agent4: 输出Agent    │ → 输出 analysis.json
    │ Agent5: 回复Agent    │ → 唯一对外输出
    └─────────────────────┘
```

## 指挥模式

**协调器按照八层体系，一步步指挥分析Agent执行。**

### 分析流程

**核心原则：画像先行。排盘+格局之后必出画像，后续层基于画像做场景推演。**

**流程：**
```
第一二层：排盘+格局 → 基础数据
画像层：人物画像 → 这个人是谁
第三-八层：专项分析 → 这种人面对XX会怎样（基于画像推演）
```

1. 每层分析结果必须存JSON（references/layerX.json）
2. **画像层在第一二层之后必做**，输出portrait.json
3. **后续每一层必须读取portrait.json**，用画像做上下文
4. 所有层完成后，bazi-responder读取JSON生成侧写回复
5. **侧写输出后，审核agent检查侧写内容是否与JSON数据一致**（正印写成偏印这种错误要拦住）
6. **只有bazi-responder可以发送消息给用户**
7. Responder不关心skill加载步骤，只读JSON，用命理师视角输出

### 各层JSON输出格式

每层分析完成后，存到`/Users/guanmian/.hermes/profiles/main/skills/bazi-system/references/layerX.json`：

```json
{
  "layer": X,
  "name": "层名称",
  "content": {
    // 该层的分析内容
  },
  "summary": "一句话总结"
}
```

## 关键规则

1. **🚨 排盘脚本是第一步，没有例外。** 即使用户只是随口说"帮我看看这个八字"，也必须先跑JS排盘脚本获取正确的十神。绝对不能手算十神——AI手算错误率极高（甲见丁=伤官非食神，甲见酉=正官非七杀，甲见卯=劫财非比肩）。用户原话："我们八字系统不是有完整的js计算吗"
2. **画像层在第一二层之后必做**，不能跳过。没有画像，后面的分析就是通用断语
3. **后续每一层必须读取portrait.json**，用画像做上下文进行场景推演
4. **后面layers没实现不影响前面的**，先把能做的做好
5. **每层都要跑**，不能跳过。第一二层排盘格局→画像→第三层六亲→第四层专项→第五层运势
6. **分析结果必须存JSON**：每层结果存到references/layerX.json
7. **bazi-responder是唯一对外输出**：其他Agent的结果都在内部流转，只有responder可以发送消息给用户
8. **Responder不关心skill加载步骤**：只读JSON，用命理师视角输出（侧写模式）
9. **⚠️ 侧写输出后必须经过审核agent检查**：逐条核对侧写内容是否与JSON数据一致，十神判断错误（如正印写成偏印）是严重错误
10. **⚠️ 不要把正印写成偏印**：甲子日柱子水=正印，不是偏印。排盘脚本标注正确但侧写可能搞混——性格怎么样、性冷淡还是啥、健康有什么问题
11. **不要前言不对后语**：如果不确定内容是否已存在，先检查再说。不要一会儿说"已经写了"一会儿说"需要补充"

## 两种分析模式

### 模式A：传统分层（默认）
按层执行：排盘→格局→性格→六亲→专项→运势→调理

**适用场景：**
- 用户只问一个领域（如"看婚姻""看事业"）
- 过三关快速验证
- 不需要全面画像

### 模式B：画像驱动（全面分析时用）
```
Phase 1: 排盘 → 画像（bazi-portrait）
Phase 2: 画像分发给各专项Agent，每个Agent用画像做上下文
Phase 3: 综合输出，以画像为主线串联各领域
```

**适用场景：**
- 用户要全面分析
- 用户问"这个人会怎样"
- 需要场景推演而非通用断语

**画像驱动的核心洞察：** 同一个命理特征，不同性格的人会做出不同选择。画像决定了面对命理特征时的行为方式。

**选择逻辑：**
- 用户只问一个领域 → 模式A
- 用户要全面分析或"这个人会怎样" → 模式B
- 过三关 → 模式A

**画像驱动的详细流程见 `bazi-portrait-orchestrator` skill。**

### 六亲分析（宫位为主，星神为辅）

**核心原则：看落宫的五行对六亲星的生克关系。**

| 六亲 | 宫位 | 六亲星 |
|------|------|--------|
| 父亲 | **月干**（不是整个月柱） | 偏财（男命） |
| 母亲 | **月令**（月支本气） | 正印/偏印 |
| 兄弟姐妹 | 月柱整体 | 比肩/劫财 |
| 配偶 | 日支（夫妻宫） | 正财（男命）/正官（女命） |
| 子女 | 时柱（子女宫） | 正官/七杀（男命）/食神/伤官（女命） |
| 祖辈 | 年柱 | 年干主父系，年支主母系 |

**断事流程（6步）：** ①确定断什么 → ②找对应宫位 → ③看宫位旺衰/冲克/空亡 → ④**看宫位五行对六亲星的生克（核心）** → ⑤找六亲星位置（透干/藏干/不显）辅助验证 → ⑥综合判断

**父亲分析（月干为宫位）：** 月干生偏财=父亲有助力；同五行=关系一般；月干克偏财=父亲受压制/健康不好；偏财生月干=父亲消耗大。两头挂凶象：两头比肩+偏财不显→父亲早亡；正印两头挂→父亲健康很不理想（正印是偏财忌神）。

**母亲分析（月令为宫位）：** 月令生母星=有助力；同五行=关系一般；月令克母星=受压制/健康不好；母星生月令=消耗大。**月令力量最大**，月令克六亲星的影响远大于其他位置。

**六亲Pitfalls：** 父亲宫位是月干不是整个月柱｜母亲宫位是月令不是月干｜第④步看五行生克不是看十神｜宫位为主星神为辅（宫和星不一致时看宫位）｜六亲不依赖画像（画像只影响相处模式）

2. **用神忌神必须格局法推导**，不能抄脚本输出
3. **偏印格是凶格**，喜财来破印
4. **流年年份必须准确**：2024=甲辰...2030=庚戌
5. **流年必须结合大运**分析
6. **子时(23-23:59)算第二天**子时（日期+1，hour=0）
